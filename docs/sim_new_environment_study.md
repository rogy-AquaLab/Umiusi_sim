# sim データは「初見の会場」で効くか（E3 完全ホールドアウト実験）

2026-10-03。風船検出器 TinyBalloonNet（width 16, input 256）。

## 結論

- 汎用（default プロファイル）sim は、初見会場への頑健性を上げなかった。むしろ下げた（全体 F1 0.35 → 0.29 / 0.22）。
- 会場の見た目に合わせた sim（pool0913 プロファイル）を real に混ぜると、初見会場の F1 が 0.34 → 0.43〜0.47 に上がった（2 seed で再現）。ただしこのプロファイルは E3 の見た目を見て調整したもので、上限値として扱う。
- どの条件でも E3 の青は 0（後述）。会場固有の色の見え方は、汎用 sim でも real でも補えない。
- 会場初日の運用方針
  1. 出発点は real 中心のモデルにする。汎用 sim を混ぜたり事前学習に使ったりしない。
  2. 会場に着いたら、最初の数分の映像から水色・照明・風船色の見え方を拾い、`gen_sim_dataset.py --profile` 相当の会場プロファイルを作る（pool0913 と同じ手順）。
  3. その sim を real と混ぜて（real 約 70%、sim 400 枚、60 epoch）、model.pt から追加学習する。この学習は CPU で約 1.5〜3 h かかるので、初日の夜に回す想定にする。
  4. 会場のラベル付きフレームが数十枚でも取れたら、そちらを最優先で入れる。今回の結果は「会場データがゼロ」の場合の数字。
- conf は 0.3 より 0.4 の方が良かった（pool sim あり: F1 0.42 → 0.45 / 0.41 → 0.47）。ただし test 上で選んだ値なので、楽観的な見積もり。

## 設定

- 環境
  - E1+E2: `real0825_train.json`（YouTube 大会映像 + 8/25 自前映像、380 枚）
  - E3: 2026-09-13 プール（p0913_* / p0913b_*）。ラベル付き 640 枚、GT 642 個（赤 193 / 青 236 / 黄 213）。風船なしフレーム 312 枚
  - E4: 2026-10-01 プール（p1001*、80 枚。赤の二連風船 + 風船なしフレーム）
- test: `annotations/loeo_e3_test.json` + `loeo_e3_test2017/`（symlink）。E3 の全ラベル付きフレーム。GT は `pool0913/pool2_train.json` と `pool2_val.json` の p0913* 部分（既存評価と同じ GT。`.label.json` より 77 フレームで箱が少なく、主に `_pip` フレームの追加箱が外れている）。
- train（E3 は 1 枚も含まない。assert で確認済み）
  - `loeo_real_train.json`: E1+E2+E4、460 枚
  - `loeo_real_sdef_train.json`: 上の real を 2 回繰り返したもの + sim_train 400 枚（real 70%）
  - `loeo_real_spool_train.json`: 上の real を 2 回繰り返したもの + sim_pool 400 枚（real 70%）
- 学習: `tools/perception_train.py` を lr 5e-4、batch 8、input 256 で回した。混合データは real の繰り返し回数を揃えるため 60 epoch、それ以外は 120 epoch。
- 評価: `umiusi_perception.eval` と同じハーネス（IoU 0.3 以上、色一致、conf 0.3、input 256）を色別に集計した。

| 条件 | 初期値 | 学習データ |
|---|---|---|
| R | model.pt（camp3_mix） | real |
| R_scratch | ランダム初期化（lr 2.5e-3） | real |
| R+S_def | model.pt | real + default sim |
| S_def→R | camp3_sim.pt（default sim のみで学習） | real |
| R+S_pool | model.pt | real + pool0913 sim |

注意: `examples/balloon_detector/model.pt` は camp3_mix と同一ファイル（md5 一致）。これは default sim と旧 real 161 枚で学習したもの。そのため「R」はすでに default sim の事前学習を受けている。sim をまったく使わない基準は R_scratch。

## 考察

- E3 の青は、照明とホワイトバランスのせいで淡い藤色〜白っぽく写っており、学習データ中の青（濃紺〜水色）とまったく違う。そのため全条件で再現率が約 0 になる。E3 の GT の 37% が青なので、全体 F1 の天井は約 0.6 になる。
  - 会場に合わせた sim だけが、青を少し拾えた（再現率 0.03〜0.05）。それでも不十分。
- default sim が悪化させた理由（推測）: default sim の水は青く、風船の色の分布も E3 と逆方向にずれている。このため、色の事前分布が「E3 と違う会場」側に引っぱられる。sim のみのモデル（camp3_sim）を E3 にかけると FP 2887 と大きく崩れており、これと整合する。
- pool0913 sim が効く理由: E3 の水色・反射・風船の見え方を真似ているから。これは「会場の見た目を事前に知っていた」ことに相当する。
  - 本番では会場の映像を見てからプロファイルを作ることになるので、今回の数字はその手順がうまくいった場合の上限にあたる。

## 注意点と残リスク

- pool0913 プロファイルは E3 を見て調整しているので、R+S_pool の数字はリークを含む上限値。本番の会場で同じ精度のプロファイルを短時間で作れるかは未検証。
- seed は R と R+S_pool のみ 2 本で、差（約 +0.1）は seed 間のばらつき（約 0.02）より十分大きい。R+S_def、S_def→R、R_scratch は 1 seed のみ。
- テストした初見環境は E3 の 1 つだけ（E1+E2 や E4 をテストに回す LOEO はやっていない）。
- 混合比（real 70% / sim 400 枚）と epoch 数はそれぞれ 1 設定しか試していない。S_pool→R（pool sim で事前学習してから real で追加学習）も未実施。
- real0825_val は model.pt の学習に使った旧 real（train_real）と一部重なっている可能性があるので、参考値として扱う。
- conf 0.4 は test 上で選んだ値。
